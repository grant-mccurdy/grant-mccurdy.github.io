Reading Assessment Evidence

A short, self-paced course that helps teachers move from assessment results to a defensible next instructional step.

Audience
Teachers comfortable with percentages, new to assessment-data interpretation.
Deliverable
Three modules, formative feedback, and a self-reviewed decision brief.
Status
New portfolio demonstration. Human review and learner testing pending.
Open courseDownload offline course

Design brief

The design hypothesis is that teachers may recognize an average but still need practice distinguishing score variation, missing evidence, and justified action. This is a proposed learner need, not a finding from interviews or a completed needs assessment.

The course uses a small fictional mathematics-team scenario rather than a complex dashboard. Learners compare eight scores per class, interpret a ten-student exit ticket, and write a short recommendation. No prior software skills are required.

Estimated duration: 25 minutes, not yet validated through learner testing. There are no time limits, locked modules, or claims of certification.

Alignment

  1. Compare distributions: read a dot plot and equivalent table, calculate ranges, then distinguish equal means from equal needs in a scenario question.
  2. Handle missing evidence: compare 6/8, 8/10, and 6/10, then select a summary that states the denominator and separates nonresponse.
  3. Choose proportionate action: examine an evidence-interpretation-action example, then select a targeted response and fresh follow-up check.
  4. Transfer: write or verbally rehearse a decision brief, then use four criteria: evidence, limitation, action, and follow-up. A model response supports comparison; writing is not automatically scored.

Incorrect options target specific misconceptions. Feedback explains the reasoning and permits revision; changing an answer clears its previous check result. Three correct checks represent success on these items, not demonstrated mastery.

Access and choice

The design draws on CAST's UDL framework and W3C page-structure guidance.

  • Representation: graphics have descriptive alternatives; all dot-plot values appear in a table. Color is paired with labels and position.
  • Engagement: a realistic, low-stakes teaching decision; unrestricted module navigation; explanatory feedback and retries.
  • Action and expression: a brief can be prose or bullets, or rehearsed aloud before a short typed summary. The rubric is constant across these options. Audio recording is not implemented.
  • Pacing and access: no autoplay or timers, browser-local saving with a storage-unavailable fallback, a printable packet, and an offline download.

Automated checks cover all module views at mobile and desktop widths, labeled forms, heading structure, image alternatives, and detected contrast issues. Keyboard checks cover navigation focus, answer entry, feedback, and reset confirmation. Captions are supplied for the silent walkthrough. Screen-reader and real-device testing, independent accessibility review, and learner evaluation remain pending. These checks are not a WCAG conformance certification.

The editable graphics are the evidence pathway and the distributions plot. Their reproducible source is retained with the project. The downloadable course contains the HTML, CSS, JavaScript, and graphics; it is a standalone web package, not an IMS Common Cartridge or Canvas export.

Evaluation plan

Before presenting the sample as validated learning design, ask three to five teachers to complete it and think aloud. Record navigation obstacles, interpretations of the denominator, reasoning behind changed answers, and the quality of the final brief using the four criteria.

Review any ambiguous distractors, unnecessary reading load, and accessibility barriers. A subsequent transfer task should use a new dataset rather than repeat these items. No completion rates, learning gains, client adoption, or learner feedback have been measured.

A Canvas-specific sample would require import or rebuilding inside an authorized Canvas course, validation there, and a separate recording. This web sample does not fulfill that platform-specific requirement.

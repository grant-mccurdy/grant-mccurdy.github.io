Evidence & Methods

Every technical claim should lead to something a reviewer can inspect.

This site is a presentation layer, not an alternate source of project truth. It explains the problem, decision, and relevance; project briefs and repositories retain the evidence, validation, implementation detail, status, and limitations.

Evidence Model

From claim to source, without overstating the work

  1. 01
    State the problem and decision

    Start with the learning, assessment, operational, or analytical need—not a tool list.

  2. 02
    Name the system and contribution

    Describe what the public artifact establishes and keep ownership language within the available project evidence.

  3. 03
    Attach evidence and validation

    Link the working interface, report, source, tests, data contract, model card, or review packet that supports the statement.

  4. 04
    Preserve status and limits

    Distinguish a working public artifact from a review-gated prototype, planned extension, or production deployment.

Reading The Portfolio

Evidence types stay distinct

Working artifact

Open and use it

A hosted dashboard, analytic workspace, report, or retrieval surface demonstrates a bounded public capability.

Review-gated prototype

Inspect the controls

The workflow demonstrates architecture and review behavior; it does not imply production integration or deployment.

Methods evidence

Follow the analysis

Model cards, reports, diagnostics, and validation artifacts show how conclusions were produced and constrained.

Public-safe boundary

Know what is excluded

Synthetic, generated, aggregated, sanitized, public, or permission-safe inputs keep private institutional records outside the portfolio.

Case-Study Template

A consistent review path

New and revised case studies should use this structure so a reviewer can evaluate relevance and proof without hunting across pages.

  1. 01Problem

    The need, user, and decision the work supports.

  2. 02Role

    The contribution established by project evidence.

  3. 03System

    The workflow, interfaces, and technical path.

  4. 04Evidence

    The artifacts, source, tests, and validation.

  5. 05Outcome

    What the artifact or analysis demonstrates.

  6. 06Limitations

    Prototype status, data boundary, and excluded claims.
